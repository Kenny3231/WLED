Le point de départ

Je voulais mettre en place deux panneaux LED de 128 × 64. Je n'ai pas pu aller plus loin : les réglages m'interdisaient de saisir 256 et, quand j'y parvenais, la valeur n'était pas prise en compte après un redémarrage. J'en ai déduit que certaines valeurs étaient codées sur 8 bits.

Pourquoi 256 posait problème

Un nombre stocké sur 8 bits va de 0 à 255. Cela suffit pour numéroter 256 colonnes (de 0 à 255), mais pas pour écrire le nombre 256 lui-même : il revient à 0.

Dans WLED, la limite prenait deux formes :

  • Des variables sur 8 bits, par exemple la largeur et la hauteur d'un panneau.
  • Un contrôle explicite au démarrage : toute dimension supérieure à 255 était refusée, et WLED repassait en bande LED classique (1D). C'est ce qui donne l'impression que la valeur n'est pas enregistrée.

6 fichiers, 66 lignes ajoutées et 25 retirées, en deux commits. Aucune fonction de WLED n'a été supprimée.

La limite est volontairement de 256 : rien de plus grand n'a été testé. Hormis le symptôme décrit au point de départ, ces défauts ont été repérés en lisant le code.

Comment l'utiliser

Matériel testé : ESP32-S3 avec 16 Mo de flash et 8 Mo de PSRAM octale, brochage HUB75 « MoonHub75 », deux panneaux 128 × 64 chaînés (sortie du premier vers l'entrée du second).

Les panneaux HUB75 consomment beaucoup de courant. Utilisez une alimentation 5 V adaptée, et ne les alimentez pas par la carte ESP32.

1. Compiler et flasher

Il faut PlatformIO et Node.js. Sous Windows, lancez la compilation depuis PowerShell ou l'invite de commandes : l'outil d'installation d'Espressif refuse de fonctionner sous Git Bash.

git clone -b wide-matrix https://github.com/Kenny3231/WLED.git
cd WLED
npm ci
pio run -e esp32s3dev_16MB_opi_hub75 -t upload

Utilisez un dossier PlatformIO séparé. Lors des essais, la plateforme ESP32 de WLED a cassé une installation PlatformIO existante dans le dossier par défaut. Avant pio run, définissez la variable PLATFORMIO_CORE_DIR, par exemple sous PowerShell : $env:PLATFORMIO_CORE_DIR = "C:\pio-wled". Les essais ont été faits sous Windows avec un tel dossier.

Avant de flasher une carte déjà configurée, sauvegardez vos réglages et vos préréglages (page « Security & Updates »).

2. Régler la sortie LED

Dans « LED & Hardware », choisissez le type HUB75 (Half Scan) avec ces valeurs. Le type de balayage dépend de vos panneaux.

Taille d'un panneau128 × 64
Nombre de panneaux2
Disposition (lignes × colonnes)1 × 2

3. Créer la matrice

Dans « 2D Configuration », choisissez « 2D Matrix » avec un seul panneau de 256 × 64, décalage 0 × 0. Enregistrez, puis redémarrez.

Après un enregistrement sur la page 2D, la couleur du segment peut devenir noire : un aplat n'affiche alors plus rien. Un redémarrage l'a rétablie lors des tests. Ce comportement a aussi été observé en 128 × 64.

Ce qui a été testé

  • La matrice 256 × 64 est conservée après redémarrage, et l'auteur du fork a constaté une image correcte sur ses deux panneaux.
  • Après le second commit : aperçu en direct vérifié au pixel près (256 × 64, 256 × 3, 63 × 130) ; valeurs de panneau absurdes refusées sans plantage ; ledmap 256 × 64 accepté ; ledmaps trop grands refusés en conservant la matrice 256 × 64 ; 8 préréglages lancés sans redémarrage.
  • Sur la première version publiée, avant le second commit : 218 effets lancés à la suite en 256 × 64 avec des transitions variées, sans redémarrage ni erreur (mémoire libre minimale : environ 102 Kio). Trois effets sont restés noirs dans l’aperçu (Image, Copy Segment, Sunrise) ; la cause probable (fichier image, second segment, démarrage sombre) n’a pas été vérifiée. Oscillate ne remplissait qu’une moitié sur la mesure courte ; mesuré plus longtemps sur une version antérieure, il couvrait les deux.
  • Les 16 tests du dépôt pour l'interface web réussissent.
  • Réglages logiciels essayés sans changer les panneaux : 128 × 64, 64 × 256, 256 × 16 et 256 × 4. Les trois derniers l'ont été sur une version antérieure, qui différait par une ligne de l'effet Octopus.

Limites connues

  • Une seule carte et un seul environnement de compilation ont été testés.
  • Le balayage des effets détecte un écran noir ou coupé en deux, pas un rendu déformé.
  • Non testés : plusieurs panneaux 2D séparés, dalle physique de 256 de haut, pleine luminosité sur une longue durée.
  • Certains effets lourds sont peu fluides sur 16 384 pixels : environ 8 à 10 images par seconde (mesuré sur une version antérieure).

Transparence sur l'IA

In English

This WLED fork accepts a 2D matrix dimension of 256 pixels, for example two chained 128 × 64 HUB75 panels. Upstream rejected any dimension above 255 and fell back to a 1D strip. Build the wide-matrix branch with pio run -e esp32s3dev_16MB_opi_hub75. The maximum is deliberately 256; only one ESP32-S3 board was tested. Developed with AI assistance.
